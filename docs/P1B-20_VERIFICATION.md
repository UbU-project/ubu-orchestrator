## Literal readings and ambiguities

- Response status is separate from stored Plan lifecycle status. Partial Plans
  remain admitted so Calendar, projection, repair and next-action keep using them.
  Existing structural/legitimacy failures can still reject; “always returns a
  Plan” applies to the capacity scenarios, not a request with no possible steps.
- New reports are top-level `unplaced_tasks`, as section A explicitly requires;
  the larger design document's nested diagnostics object is not introduced here.
- “Smallest id most protected” fixes the omission id tie to largest id first.
  Missing deadlines are least protected at equal value.
- Pre-dispatch messages give only the excluded Task id, not a complete causal
  graph. Their original explanations are preserved and reference lists remain
  empty; kernel reports carry the specified dependency refs.
- Eligibility is recomputed from immutable base units separately for each branch
  after omissions. Chunk refs are captured at exclusion, so the report records
  the eligible chunks considered when that Task was removed.
- The requested twelve new partial tests plus replacing one sweep test with five
  add 16 tests, which would give 72. One additional transitive fixed-protection
  and forward-closure regression brings the required total to 73; the new
  partial-placement file still has exactly twelve test functions.
- `static_placement.rs` uses JSON Task builders at the pinned baseline, not
  TaskSpec literals. Its default-false deserialization already covers the marker;
  the changed skeleton return access and kernel cargo fmt were applied.
- The six repository-root kernel `tests/` files are stale, uncompiled copies:
  the workspace root has no `[package]`. They remain byte-for-byte untouched and
  diverge further from the compiled crate tests. This is recorded, not repaired.
- The measured clippy baseline is 11, not the ticket's stated 16. Preserving the
  actual diagnostic set takes the “do not fix them, and do not add any” rule
  literally rather than creating warnings to match the stale count.
